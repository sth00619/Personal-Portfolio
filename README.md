## 원칙

이 레포의 모든 프로젝트는 세 가지를 갖춰야 완료로 인정합니다.

1. **Eval** — 정량 지표 (Recall@10, false-hit rate, Gini, ECE, OPE 추정 오차 등)
2. **Number** — 실제 측정한 숫자
3. **Tradeoff** — 왜 이 설정을 골랐는지, 다음에 무엇을 검증할지 말로 설명 가능

각 프로젝트는 독립 완료가 아니라 이전 프로젝트의 한계에서 다음 가설이 출발하는 연결된 흐름입니다. WO-01의 검색 평가 하네스가 WO-02의 생성 품질 분리로 이어지고, WO-02에서 발견한 컨텍스트 선택 문제가 WO-03의 정책 설계 감각으로 이어지는 식입니다. WO-07~09는 광고·추천 도메인에서 같은 원칙을 반복합니다. WO-07의 확률 캘리브레이션이 WO-08의 입찰 전략 평가로 이어지고, WO-08에서 다룬 관측 지원 범위 문제가 WO-09의 반사실 평가(OPE) 설계로 이어집니다. WO-10~11은 인과추론과 조합최적화로 영역을 넓힙니다 — WO-10은 예상과 다른 결과(업리프트 모델이 기준선을 못 이김)를 숨기지 않고 보고하는 사례이고, WO-11은 공개 벤치마크로 구현을 먼저 검증한 뒤 시뮬레이션으로 확장하는 접근을 보여줍니다. WO-12는 검증 방식을 예측 문제로 확장합니다 — 분위수 예측 구간이 선언한 신뢰수준을 실제로 지키는지 분자·분모까지 재현하고, 가설과 반대로 나온 집계 레벨 결과도 그대로 보고합니다. WO-13은 같은 검증 엄격성을 분류 문제로 가져갑니다 — 무작위 분할이 만드는 과대평가를 시간 분할로 드러내고, 결측 피처 제거와 임계값 선택도 사후 최적화 없이 검증 구간 안에서만 결정합니다. WO-14는 WO-06의 신용평가 작업을 다중 테이블 조인으로 확장합니다 — 판별력 이득과 입력 안정성(PSI)을 같은 비교에서 측정해, 가설과 다르게 나온 결측 피처 결과도 구성 효과까지 밝혀 그대로 보고합니다. WO-15는 같은 검증 습관을 SQL 기반 분석으로 가져갑니다 — 고객 식별자를 잘못 고르면 재구매율이 0%로 오집계된다는 함정을 먼저 수치로 드러내고, 낮은 재구매율과 희소 월의 허위 급락도 숨기지 않고 원인까지 분해해 보고합니다. WO-16은 검증 대상을 평가 데이터 자체로 넓힙니다 — 모델이 생성한 SQL과 벤치마크 정답 SQL을 함께 의심하며, 가드레일의 안전성과 실행 정확도를 분리해 측정하고 실패 사례 일부를 수동 재검토해 모델 오류와 정답 데이터 경계 사례를 구분해 보고합니다. WO-17은 WO-01~02의 하이브리드 검색을 상품 검색 랭킹으로 확장합니다 — 이진·등급 관련도 두 기준 모두로 평가해, 개선 방향은 같지만 크기는 다르다는 사실을 함께 보고하고, 라벨 문서의 후보 상한과 실제 데이터가 다른 것을 발견해 임의로 자르지 않고 그대로 보존합니다. WO-18은 검증 대상을 ML 지표에서 백엔드 신뢰성으로 넓힙니다 — Spring Boot 백엔드 경력과 직결되는 LLM 게이트웨이를 만들어, 장애조치·속도 제한·비용 집계를 실측하고, 정상 응답에서는 완벽히 일치하던 비용 장부가 타임아웃 상황에서는 상당량 누락된다는 사실을 숨기지 않고 보고합니다. WO-19는 WO-07의 검증된 평가 자산을 재사용해 모델 회귀 탐지기 자체를 벤치마크합니다 — 전체 정확도를 고정한 채 한 세그먼트만 의도적으로 악화시키는 통제 실험으로 평균 지표가 숨기는 회귀를 찾아내고, 통계적 유의성만 본 거짓 양성률과 실질 크기 기준까지 더한 운영 거짓 양성률을 구분해 표본 크기별 탐지력을 정직하게 보고합니다. WO-20은 LLM 프롬프트 비교에 같은 통계 엄격성을 적용합니다 — SQuAD 2.0 전체 dev셋에서 두 프롬프트를 쌍체 비교하고, 채점기가 문장형 응답 보류를 놓쳤던 버그를 발견해 수정 전후 효과 크기(+35.60%p→+20.96%p)가 어떻게 달라졌는지 그대로 공개하며, 소표본 방향 일치율과 통계적 검정력이 다른 질문임을 구분해 보고합니다. WO-21은 검증 대상을 텍스트에서 문서 레이아웃으로 넓힙니다 — 같은 OCR 텍스트에 레이아웃 좌표를 더했을 때 엔터티 연결 성능이 실제로 오르는지 정답 엔터티를 전제로 측정하고, 공식 평가 문서 50개 중 3개는 답변 후보가 없어 실제 평가 대상이 47개임을 숨기지 않고, 오류 검토 20건을 전체 분포로 일반화하지 않습니다. WO-22는 WO-18의 게이트웨이 신뢰성을 비용 정책으로 확장합니다 — WO-20의 저장된 응답을 재사용해 난이도 라우팅과 의미 캐시의 비용 절감을 측정하되, 두 경로 모두 품질 손실을 동반한다는 사실과 캐시 정밀도가 학습 데이터에서는 통과하고 홀드아웃에서는 기준에 못 미친다는 사실을 비용 절감 수치와 같은 자리에서 공개합니다. WO-23은 검증 범위를 모델 출력에서 데이터 적재 구조 자체로 넓힙니다 — 실제 분기 정정 공시 하나를 접수번호별 XBRL 원본까지 추적해, 시점 기준 조회가 정정 전·후 원본과 완전히 일치하는지 확인하고, 덮어쓰기 방식이 실제로 과거 값 몇 건을 잃는지 수치로 보여주며, 합성 성능 벤치마크와 실제 공시 검증을 분리해 보고합니다. WO-24는 검증 대상을 데이터 구조에서 표본 설계 자체로 넓힙니다 — 같은 모멘텀 전략에 현재 상장 표본과 상장폐지 종목 표본을 각각 적용해 생존 편향의 크기를 직접 측정하고, 숨어 있던 일일 재조정 회계 오류와 동률 비결정성을 발견해 수정한 뒤의 수치만 최종 결과로 보고하며, 이 표본에서 관측한 민감도를 한국 시장 전체의 보편적 생존 편향 효과로 일반화하지 않습니다. WO-25는 검증 대상을 프롬프트 버전에서 LLM 적용 방법 자체로 넓힙니다 — WO-20이 같은 모델에서 프롬프트 두 버전을 비교했다면, WO-25는 같은 베이스 모델에서 제로샷·퓨샷·RAG·LoRA 네 적용 방법을 공식 GSM8K test 전체로 비교하고, validation에서 고른 LoRA 설정이 공식 test에서는 zero-shot보다 낮게 나온 사실과 MMLU 100문항 표본에서 관측한 -2.00%p 변화를 모두 그대로 보고합니다.
