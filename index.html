01 금융 서비스

FinAI 금융 분석·리포트 서비스

개발 작업 · 구현 확인

시세와 재무제표를 서비스에서 사용할 수 있는 데이터로 바꾸고, 계산된 지표를 조회·분석·리포트로 연결하는 프로젝트입니다.

JavaSpring BootJPABigDecimal시계열 정렬SMA · RSI

다룬 문제

종목별 시세와 회계기간별 재무 데이터는 식별자·갱신 주기·금액 단위가 다릅니다. 이를 확인하지 않으면 같은 비율도 다른 의미가 됩니다.

작업과 산출물

시세·재무 데이터 모델, 숫자 파싱, 가격 이력 기반 지표 계산 경로와 리포트 화면 개선 작업을 진행했습니다.

전처리·수식·검증 범위 읽기 ＋

데이터를 준비하는 과정

재무 금액의 쉼표와 공백을 제거한 뒤 BigDecimal로 변환하고, 해석할 수 없는 금액은 적재 단계에서 건너뛰는 경로를 두었습니다. 가격 이력은 날짜 내림차순 조회 결과를 오래된 순으로 바꿔 계산합니다. 재무 데이터에는 회계연도·분기·계정·통화·연결/개별 구분을 담습니다.

계산과 표현

이동평균은 관측 기간의 종가 평균으로, RSI는 상승·하락 폭의 평활 평균으로 계산합니다. 필요한 가격 이력이 모자랄 때는 결과 대신 데이터 부족 상태를 반환하는 경로가 있습니다. 금액과 비율의 반올림 자릿수를 명시해 화면에 전달합니다.

검증 범위를 구분한 이유

재무비율 산출 코드는 있지만, 공급자별 금액 단위와 결산기간의 정합성까지 검증된 성과로 내세우지는 않습니다. 표준 정의와 추가 대조가 필요한 지표는 완성된 매매 신호로 소개하지 않았습니다. 실제 투자 수익률이나 예측 정확도를 측정한 프로젝트가 아닙니다.

금융 개발에 연결되는 역량: 수치형 데이터 모델링, 입력 해석, 계산 전제 확인, 결과 상태 전달.

02 캡스톤 · 협업

FinanceManus / FinanceX 금융 리서치·분석

협업 · 구조·이론 검토

금융 분석 결과를 사용자에게 어떻게 설명하고, 계산값과 출처를 어떻게 구분해 보여줄지 고민한 캡스톤 경험입니다.

UI/UX · 문서화Python 계산 구조 검토수익률 · 공분산CAPM근거 기반 해석

참여 범위

분석 결과를 전달하는 UI/UX와 시스템 구조 분석·문서화를 중심으로 참여했습니다. 팀 시스템의 계산 개념을 이해하고 결과의 의미를 설명하는 데 초점을 두었습니다.

이해하고 연결한 개념

공통 날짜의 가격 정렬, 수익률 변환, 포트폴리오 위험, CAPM의 기대수익률과 관측 수익률 차이가 결과 화면에서 갖는 의미를 검토했습니다.

금융 이론을 제품 맥락으로 읽기 ＋

계산보다 먼저 확인하는 입력

여러 종목을 비교할 때 관측 날짜를 맞추고, 통화·기준시점·표본 길이를 확인합니다. 가격 수준 자체의 상관관계와 수익률의 상관관계는 다릅니다. 공통 날짜를 선택하면 비교는 쉬워지지만 표본이 줄어드는 한계가 있습니다.

화면에서 설명해야 하는 모델의 가정

포트폴리오 변동성에는 자산별 변동성뿐 아니라 공분산이 들어갑니다. CAPM은 무위험수익률과 시장위험 프리미엄, 베타에 기초한 모형이며 미래 수익을 보장하지 않습니다. 과거 평균의 연율화와 실제 복리 수익률을 같은 값으로 표시해서는 안 됩니다.

기여와 공개 범위

이 페이지에서는 이론의 이해와 결과 전달 관점을 설명합니다. 내부 검색·추론 절차, 검증 정책의 상세 조건, 원본 자료와 팀의 구현 코드는 공개하지 않습니다. 서비스 전체 성능을 개인 기여율로 환산하지 않았습니다.

금융 개발에 연결되는 역량: 모델 가정 해석, 데이터 상태를 반영한 UI 요구사항, 기술 구조 문서화와 협업.

JavaSpring BootWebClientSwaggerPostgreSQL시계열 모델

다룬 문제

인증 토큰의 유효기간, 실전/모의 환경, 응답 필드의 자료형이 데이터 수집의 안정성에 영향을 줍니다.

작업과 산출물

API 호출과 인증을 나눈 테스트 구조, 토큰 재사용·갱신 경로, 시각과 종목을 함께 식별하는 가격 저장 모델을 구성했습니다.

데이터 모델과 운영 관점 읽기 ＋

가격·거래량과 등락률은 의미에 맞는 자료형으로 구분합니다. 시계열에는 시각과 종목 식별자가 함께 필요하며, 날짜만 같은 두 시장의 데이터가 동일한 관측 시점을 뜻하는 것은 아닙니다.

현재 코드에서 인증·조회 경로와 시계열 엔티티를 확인할 수 있습니다. Redis·TimescaleDB를 포함한 저장·캐시 구조의 설계와 전체 수집 운영 검증은 구분합니다. 처리량·지연시간·장애 복구 성능을 측정했다고 주장하지 않습니다.

금융 개발에 연결되는 역량: 외부 시스템 연동, 인증 수명주기, 시계열 키 설계, 데이터 수집과 분석의 분리.

04 금융 정보 품질

금융 콘텐츠 파이프라인 수치의 정확한 전달

개발·검증 진행

검증한 금융 숫자가 대본·자막·이미지로 전달되는 과정에서 변형되지 않도록 품질 조건을 관리한 경험입니다.

Python · JavaOCR데이터 계보결정론적 표시회귀 검증

다룬 문제

생성 모델이 그럴듯한 숫자나 문자를 만들거나, 작은 글자가 OCR에 잡히지 않으면 잘못된 정보가 결과물에 남을 수 있습니다.

작업과 산출물

승인 수치·문구와 결과의 대조, 미검출 원인 분리, 공통 품질 조건으로의 반영, 회귀 검사와 실물 검토를 나누어 진행했습니다.

금융 정보 신뢰성과 연결하기 ＋

수치는 검증된 입력에서 가져오고 표시 과정은 결정론적으로 처리하는 원칙을 세웠습니다. “값을 읽지 못함”을 “일치함”으로 간주하지 않으며, 숫자와 단위를 함께 해석합니다.

승인 원문과 산출물의 연결을 추적하고, 개별 예외를 늘리기보다 공통 검증 경계를 보완하는 데 집중했습니다. 자동 검사 결과와 사람이 확인한 품질을 구분합니다. 생성 성공이나 테스트 통과만으로 최종 콘텐츠의 완성을 선언하지 않습니다.

공개 범위: 문제·접근·배운 점. 원본 입력, 상세 프롬프트, 내부 비용 정책, 전체 파이프라인 설계와 로그는 포함하지 않습니다.

Python · PySparkSQL · MySQLMongoDB형 변환GROUP BY · AVG
금융 데이터 업무에 연결되는 기반 읽기 ＋

금융 거래 데이터를 처리한 과제는 아닙니다. 이 경험을 금융 업무에 적용한다면 금액에는 적절한 십진 정밀도를 쓰고, 단순 평균과 거래량 가중평균을 구별해야 합니다. 금융용 데이터 파이프라인을 완성한 성과로 확대하지 않았습니다.

금액 문자열재무 금액의 쉼표·공백 제거, BigDecimal 변환파싱 실패와 실제 0원 구별. 괄호 음수 등 공급자 표현 규칙 확인.

03 / 수식과 해석

이론을 외우는 데서, 계산 조건을 설명하는 쪽으로.

일반적인 금융 개념을 프로젝트와 연결했습니다.
아래 계산 예제는 투자 성과나 실제 시장 수치가 아닙니다.

FinAI · 재무비율 산출 경로

PER · PBR · ROE

기업의 가격과 이익·자본을 비교하려면 분자와 분모의 단위, 회계 범위와 기준기간이 맞아야 합니다.

PER = 시가총액 ÷ 순이익
PBR = 시가총액 ÷ 자기자본
ROE = 순이익 ÷ 평균 자기자본 × 100

ROE는 평균 자기자본을 사용하는 일반적인 설명입니다. 프로젝트의 기말 자본 기준 계산과 구분해 읽어야 합니다. PER도 당기·최근 12개월·예상 이익을 혼용하지 않습니다.

프로젝트와 연결한 판단 ＋

재무비율 계산 경로에서 분모의 양수 조건과 반올림을 확인했습니다. 결측 계정을 0으로 취급할 수 있는 경로, 공급자 단위와 연간·분기 자료가 섞이는 경우는 추가 검증 대상으로 구분했습니다. “계산 코드가 있음”을 “모든 종목의 적정가를 평가함”으로 확대하지 않습니다.

SMA · RSI

가격의 추세와 변동 강도를 계산하는 지표입니다. 날짜 순서와 필요한 관측 수가 계산의 일부입니다.

SMAₙ = 최근 n개 종가의 합 ÷ n
RS = 평활 평균 상승폭 ÷ 평활 평균 하락폭
RSI = 100 − 100 ÷ (1 + RS)

RSI 14기간에는 초기 변화량을 얻기 위해 최소 15개 가격이 필요합니다. 이후 평균을 평활 갱신하며, 지표 구간을 매매 성과로 해석하지 않습니다.

구현과 한계를 구별하기 ＋

가격 순서를 바꾼 뒤 SMA와 RSI를 계산하고 데이터 부족을 반환하는 경로를 확인했습니다. 상승·하락이 모두 없는 가격열의 처리 정책과 다른 기술적 지표의 근사 구현은 표준 정의와 별도 대조가 필요합니다. 이 페이지는 검증하지 않은 MACD 신호를 대표 성과로 싣지 않습니다.

수익률 · 변동성 · 분산투자

자산 간 위험을 비교할 때 가격 수준보다 수익률을 사용하고, 함께 움직이는 정도를 공분산으로 반영합니다.

rₜ = Pₜ ÷ Pₜ₋₁ − 1
σₚ = √(wᵀΣw)
σ연간 ≈ σ일간 × √252

252는 연간 거래일 수의 관례적 가정입니다. 제곱근 연율화는 독립성·안정적인 분산 등의 가정에 의존하며, 관측 평균 × 252는 복리 수익률과 다릅니다.

데이터와 모델의 관계 읽기 ＋

팀 시스템에서 공통 관측일 정렬과 수익률·공분산 계산의 연결을 검토했습니다. 배당·액면분할을 반영한 수정가격인지 확인하지 않으면 수익률이 왜곡될 수 있습니다. 공통 날짜만 남기면 표본이 줄며, 관측 수 대비 자산 수가 많을수록 공분산 추정이 불안정해질 수 있습니다.

수축 추정은 공분산 추정 안정성에 관한 접근입니다. 이를 실제 수익률 개선의 근거로 제시하거나 해당 엔진을 개인이 모두 구현했다고 주장하지 않습니다.

캡스톤 · 금융 결과 해석

CAPM · VaR

베타는 시장과의 민감도, VaR는 주어진 기간·신뢰수준에서의 손실 분포를 요약하는 개념입니다.

βᵢ = Cov(rᵢ, rₘ) ÷ Var(rₘ)
E[rᵢ] = r𝒇 + βᵢ(E[rₘ] − r𝒇)

CAPM의 모형 기대수익률과 관측 수익률 차이는 미래 초과성과 보장이 아닙니다. VaR는 최대 손실 보장도, 그 한계를 넘는 손실의 평균도 아닙니다.

결과 화면에 필요한 설명 ＋

벤치마크·무위험수익률·통화·관측기간을 함께 표시해야 비교의 기준을 알 수 있습니다. 과거 수익률의 하위 분위수를 표시한다면 손실을 양수로 보고하는 VaR와 부호 관례가 다를 수 있으므로, 숫자의 방향과 기간을 설명해야 합니다.

AI 도구의 사용 자체를 금융 모델 개발이나 검증 완료의 증거로 삼지 않습니다. 산출물의 의미와 한계를 설명하는 것을 중요하게 생각합니다.

향후 적용 설계 · 미실행 분석 기능의 A/B 테스트는 어떻게 설계할까?＋

가설: 지표의 기준기간·단위 설명을 함께 보여주면 사용자의 해석 오류가 줄어든다.

주지표: 사전에 정의한 해석 과제의 정답률. 동일 문항·동일 모집 조건으로 방문자 단위 무작위 배정한다.

보조·보호 지표: 과제 완료 시간, 설명 열람률, 이탈률. 클릭 증가를 금융 판단의 정확성 향상으로 대체하지 않는다.

판정: 기준선과 최소 검출 효과를 측정해 표본 수를 정하고, 배정 비율 이상·중복 관측·반복 검정을 점검한다. 효과크기와 신뢰구간을 함께 보고한다. 현재 실제 방문자 데이터나 A/B 성과는 없다.
