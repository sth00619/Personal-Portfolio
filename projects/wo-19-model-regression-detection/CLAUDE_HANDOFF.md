## 실험 정의와 결과

- **재사용 자산**: WO-07이 체크섬·스키마·행 수·시간 순서를 확인한 Avazu 표본, WO-07의 `AvazuFeatures`, `chronological_split`, `fit_avazu_baseline`을 재사용했다. 테스트 날짜는 기존 WO-07 홀드아웃의 마지막 두 구간이다. 원본은 WO-07 `data/`에 머물며 Git 추적 대상이 아니다.
- **기준 모델 A**: 기존 LightGBM 설정(160 trees, 31 leaves, min child 100, learning rate 0.05, random state 7)의 원시 확률을 threshold 0.5로 이진화했다. 지표는 행별 정확도뿐이다.
- **사전 정의**: `device_type=0`에서 정확도 감소 5%p 이상이고, 유의수준 0.05를 적용한 세그먼트 가족 검정에서 단측 유의해야 운영 회귀 플래그를 올린다. support가 1,000행 이상인 세그먼트 `0`, `1`, `4`만 포함하고 `5`(641행)는 제외했다. 쌍체 t 검정은 Holm, 부트스트랩 상한은 가족 단위 Bonferroni를 적용했다.
- **버전 C**: 각 적격 세그먼트의 정답 중 5%와 오답 중 5%를 짝수로 교환해 같은 세그먼트 정확도를 유지했다. 전체 홀드아웃에서는 A와 같은 83.902514%, 세그먼트 0에서 79.689332%다.
- **버전 B**: target 세그먼트의 정답 중 10%를 오답으로 바꾸고, 적격 control 세그먼트의 오답에서 같은 행 수를 정답으로 바꿨다. 결과적으로 전체 정확도는 83.902514%로 동일하고 target 정확도는 69.685424%로 하락했다.
- **표본 크기 반복**: 세그먼트당 50/200/1,000행을 고정 홀드아웃에서 복원 추출하고 2,000번 반복했다. FPR·power의 Wilson 95% 구간, 유의성 전용 지표와 5%p 효과 기준을 함께 결과 JSON에 저장했다.

## 판단 장면

### 기존 검증 자산을 골든셋으로 재사용

- 상태: 이번에 새로 검증
- 맥락: WO-19는 정답 레이블이 있는 버전 비교와 세그먼트 구성이 필요하지만 새 데이터를 임의 생성하면 골든셋 구축 방법론을 평가하기 어렵다.
- 첫 가설: WO-07의 Avazu 평가 구간은 별도 검증된 시간 분할, 행별 레이블, `device_type`가 있어 모델 회귀의 고정 골든셋 후보가 될 수 있다.
- 대안: 새로운 임의 평가 데이터를 생성하거나, 행별 데이터가 남지 않은 집계 결과만 사용한다. 전자는 출처·정답 기준을 새로 만들어야 하고 후자는 paired test에 쓸 수 없다.
- 판단 기준: 기존 평가 결과와 모델 코드를 그대로 재사용할 수 있는지, 행별 레이블·세그먼트 매핑이 보존되는지.
- 실험: WO-07 `data/avazu_sample.csv.gz`를 기존 로더와 시간 분할·feature builder로 읽고 LightGBM 기준선을 재적합했다. 테스트 행 201,137개를 확인하고 sample SHA-256을 결과에 기록했다.
- 관측: `device_type` support는 0:10,236, 1:186,600, 4:3,660, 5:641이었다. 1,000행 최소 support 기준으로 `0/1/4`를 검정 세그먼트로 고정했다.
- 뜻밖의 결과: `device_type=5`는 자연스러운 네 번째 그룹처럼 보이지만 표본이 사전 최소 support에 미달했다. 네 그룹 모두를 비교하는 대신 해당 값을 배제하고 검정 가족을 3개로 기록했다.
- 결정: Avazu의 행 단위 평가셋과 기존 WO-07 모델·전처리를 사용했다. 자산 재사용 기준은 작업지시서에 있었고 실제 연결은 Codex가 판단·구현했다.
- 한계: 같은 로그와 모델 계열을 재사용했으므로 독립적인 데이터 도메인 전이를 입증하지 않는다.

### 전체 평균을 고정한 레이블 기반 변형

- 상태: 이번에 새로 검증
- 맥락: 전체 지표만으로 조용한 세그먼트 회귀를 구별한다는 목표를 검증하려면 평균 정확도 차이가 원인이 되어서는 안 된다.
- 첫 가설: target에서 정확한 행을 오답으로 바꾸고 control에서 같은 수의 오답을 정답으로 바꾸면 전체 정확도는 동일하면서 target에는 알려진 하락이 생긴다.
- 대안: target에서만 정확한 행을 오답으로 바꾼다. 구현은 단순하지만 전체 정확도도 떨어져 세그먼트 검정의 기여를 분리하기 어렵다.
- 판단 기준: 전체 정확도는 같고, target effect는 사전 정의한 5%p를 넘으며, C는 세그먼트별 정확도가 보존되는가.
- 실험: A 기준에서 B는 target `device_type=0`의 정답률을 10%p 낮추고 적격 control에서 같은 오류 수를 상쇄했다. C는 적격 각 세그먼트 안에서 정답/오답을 균형 교환했다.
- 관측: 전체 A/B/C 정확도 모두 83.902514%. target A=79.689332%, B=69.685424%, C=79.689332%. B 차이에 대한 t p=`6.8380e-237`, Holm p=`2.0514e-236`, bootstrap 95% 구간 `-10.5998~-9.4468%p`.
- 뜻밖의 결과: B가 control 세그먼트 성능을 개선해야 전체 평균이 유지된다. 이 구조는 평균지표 masking을 명확히 만들지만 실제 모델 업데이트가 이런 상쇄를 만든다고 주장할 수 없다.
- 결정: 이 변형은 모델 재학습이 아니라 레이블을 직접 사용하는 detector unit benchmark로 한정했다. 범위·구현·실행은 Codex가 했고 사용자 승인이나 기술 선택 답변은 받지 않았다.
- 한계: 이 테스트로 feature drift, label delay, calibration drift, 실제 모델 재학습 오류의 발생 확률을 말할 수 없다.

### 효과 크기 기준과 표본 크기별 검정력

- 상태: 이번에 새로 검증
- 맥락: 작업지시서의 회귀 예시는 5%p 하락과 유의성을 함께 요구한다. 처음 실험은 B를 정확히 5%p만 낮춰 작은 표본의 검정력이 경계 효과에 얼마나 민감한지 확인했다.
- 첫 가설: 경계 크기의 변화는 표본당 50행에서 상당한 측정 잡음 때문에 탐지력이 낮을 수 있다.
- 대안: 효과 기준도 10%p로 완화한다. 그러면 회귀 정의가 약해져 업무적으로 의미 있는 하락을 놓칠 수 있다.
- 판단 기준: 운영 플래그의 효과 기준은 5%p로 유지하고, 경계보다 큰 10%p의 통제 변화를 주입해 표본 크기별 power와 false-positive를 따로 본다.
- 실험: 최초 설정은 5%p 주입과 유의성 단독 규칙이었다. 결과는 표본 50에서 t/boot FPR `4.10%/6.15%`, power `10.20%/21.70%`; 200에서 FPR `4.55%/4.55%`, power `97.75%/98.70%`; 1,000에서 FPR `5.85%/5.50%`, power 모두 `100%`였다. 이를 기록한 뒤 최종 설정에서 관측 효과 하락 5%p와 보정 p 통과를 모두 요구하고 B는 10%p로 변경했다. 최종 2,000회 결과는 README와 JSON에 있다.
- 관측: 최종 10%p 시나리오의 운영 power는 표본 50에서 t/boot `56.20%/69.15%`, 200에서 모두 `99.65%`, 1,000에서 모두 `100%`. 유의성 전용 가족 FPR은 표본 50/200/1,000에서 t `3.65/5.45/5.15%`, bootstrap `5.45/4.90/4.65%`다. 통제된 C에서 5%p 운영 기준까지 적용한 family false positive는 각각 표본 50에서 `3.65/5.45%`, 200에서 `4.30/3.85%`, 1,000에서 `0/0%`였다.
- 뜻밖의 결과: bootstrap이 모든 표본에서 더 신뢰할 만하지 않았다. 50행의 bootstrap FPR은 5.45%였고 t 검정은 3.65%로 보수적이었다. 200/1,000행에서 통계적 유의성 전용 FPR은 둘 다 5% 근처였다. `0/2,000` 운영 플래그는 확률 0을 증명하지 않으므로 Wilson 구간도 보고했다.
- 결정: 5%p를 업무 효과 기준으로 유지하고, 10%p 변화의 실험 결과와 유의성-only 비교를 함께 공개했다. 샘플 크기가 커질수록 탐지력은 늘었지만, 단일 데이터·단일 통제 변형의 검정 비교를 보편적인 우열로 표현하지 않는다.
- 한계: Monte Carlo 반복은 동일 고정 표본의 복원추출이며 새 모델 학습, 사용자 단위 군집, 새 트래픽 분포는 재표집하지 않는다.

## 실행 시행착오

1. 첫 Docker 테스트에서 `scripts` 모듈 패키지 표시가 없어 테스트 수집이 실패했다. `scripts/__init__.py`를 추가하고 Python 모듈 방식으로 pytest를 실행해 3개 테스트가 통과했다.
2. LightGBM 로딩 시 Debian 이미지에 `libgomp.so.1`이 없었다. Dockerfile에 `libgomp1`을 설치했다.
3. 기존 Avazu 로더는 PyArrow-backed pandas string을 요구하고 LightGBM sklearn wrapper는 scikit-learn을 요구했다. WO-07 고정 버전 `pyarrow==22.0.0`, `scikit-learn==1.7.2`를 의존성 목록에 추가한 뒤 전체 실험을 끝냈다.

## Claude에게 넘길 때 주의

- B/C는 held-out label을 보고 이진 정답 여부를 직접 변형한 실험 버전이다. 이를 “재학습 모델이 실제로 회귀했다”거나 모델 업데이트 원인이 검증됐다고 표현하지 않는다.
- A/B/C 전체 정확도가 같다는 사실은 통제 설계 결과다. target B의 `-10.0039%p`, t/boot 근거, 반복별 FPR/power를 함께 적는다.
- `0/2,000`은 관측값 그대로 쓰고 “거짓 양성이 없다”고 일반화하지 않는다. Wilson 상한도 같이 표시한다.
- 통계적 유의성만의 FPR과 5%p 운영 효과 기준을 더한 FPR을 구별한다.
- 원본 데이터와 행 단위 결과는 전달 패키지에 넣지 않는다. README와 Notion은 기존 WO-19 페이지가 있는지 먼저 확인한다.
