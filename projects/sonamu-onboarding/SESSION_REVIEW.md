# Sonamu 준비 세션 · 판단 기록

이 문서는 공개 예제를 로컬에서 검증한 **준비 실습 요약**이다. 채용 과제의 원본 에이전트 대화 내역이나 제출용 세션 로그를 대신하지 않는다. 실제 과제에서는 해당 세션을 원본 형태로 보존하고, 이와 같은 판단 근거를 별도 리포트에 적는다.

## 목표와 역할

- 사용자: Sonamu 문서와 `examples/miomock`을 실행해, 에이전트 세션·판단 과정이 평가되는 전형에 맞는 포트폴리오 사례를 요청하고 공고 링크를 제공했다.
- Codex: 공식 문서와 예제 코드를 읽고, 도구 설치·실행·오류 진단·검증 스크립트·문서를 수행했다.
- 검증 기준: 예제 빌드, 개발 DB 마이그레이션, 관리자 화면·Sonamu UI·API 응답이 실제로 동작해야 한다.

## 관찰 → 가설 → 판정

| 관찰 | 검증과 판정 | 조치 |
|---|---|---|
| 공식 예제의 Docker Compose가 호스트 `5432`를 공개했고, DB 컨테이너는 정상 기동됐다 | 첫 마이그레이션은 `Knex: Timeout acquiring a connection`으로 실패했다. 컨테이너 안 `psql`은 정상이라 컨테이너 가동만으로 호스트 연결을 보증할 수 없었다 | 호스트에서 실제 연결 대상과 포트 점유를 조사했다 |
| 호스트 `127.0.0.1:5432`에는 기존 PostgreSQL과 Docker 프록시가 함께 보였다 | Node `pg`로 해당 주소에 접속하면 `role "postgres" does not exist`가 반환됐다. 예제 컨테이너 안에는 `postgres` 역할과 `miomock_development` DB가 있었다 | 기존 PostgreSQL은 유지하고 예제 컨테이너만 `127.0.0.1:15432`로 재매핑했다 |
| 재매핑 후 호스트에서 예제 DB에 직접 연결됐다 | 개발 DB 마이그레이션이 성공하고, `public` 테이블 21개가 확인됐다 | 앱과 HTTP 경로를 실행해 연결을 끝까지 검증했다 |
| 개발 서버가 DB 연결 및 서비스 준비를 보고했다 | `/admin`, `/sonamu-ui`, `/api/user/getMyIP`가 모두 HTTP 200을 반환했고, 브라우저에서 관리자 화면과 Sonamu UI가 보였다 | 같은 확인을 반복할 수 있게 [`scripts/smoke_miomock.py`](scripts/smoke_miomock.py)를 작성했다 |

## 배운 점과 다음 실험

`docker ps`나 컨테이너 내부의 `pg_isready`는 애플리케이션이 연결하는 **호스트 주소의 대상**을 증명하지 못한다. 에이전트가 “DB가 살아 있으니 마이그레이션 코드 문제”라고 결론 내렸다면 호스트의 실제 접속 오류와 리스너를 확인해 반박해야 한다. 설정 변경 후에는 마이그레이션과 HTTP 요청까지 다시 검증해야 한다.

**다음 단계:** 실제 채용 과제가 제공되면 원본 세션 기록을 별도로 보존하고, 에이전트 제안·반례·수정·회귀 확인을 과제 코드와 함께 제출한다. 이 준비 실습의 결과를 채용 과제 수행 결과로 표시하지 않는다.
