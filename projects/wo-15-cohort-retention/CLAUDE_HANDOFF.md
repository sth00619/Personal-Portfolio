수치는 프로젝트 실행 산출물에서 읽었다. 작업지시서가 낮은 재구매율을 숨기지 말라는 방향을 제공했고, SONG이 이번 대화에서 추가 임계값·해석 선택을 답한 기록은 없다. 본 문서의 구현·분석 선택은 Codex 자체 판단으로 표시한다.

## 판단 장면 1 — 주문 키와 고객 키를 실제 집계로 분리

- **상태**: 작업지시서의 식별자 함정을 이번 실행으로 검증.
- **맥락**: 주문마다 발급된 customer_id를 고객으로 세면 누구나 한 번만 구매한 것으로 보인다.
- **첫 가설**: 적절한 고객 단위에서는 반복 고객이 전체의 약 3% 수준일 것이다. 이는 시작 문서가 제공한 데이터 특성 가정이다.
- **대안**: customer_id, customer_unique_id, 배송 완료 주문만으로 한정한 customer_unique_id를 각각 비교.
- **판단 기준**: 고객 단위 반복 주문을 식별하면서 구매 완료의 의미를 일관되게 유지.
- **실험**: PostgreSQL customer_id_effect 생성; 전체 99,441 주문과 배송 완료 96,478 주문을 별도 모집단으로 반복 여부 집계.
- **관측**: customer_id 반복율 0%; 전체 주문의 고유 고객은 96,096명 중 2,997명(3.1188%); 배송 완료 코호트는 93,358명 중 2,801명(3.0003%). 근거: results/customer_id_effect.csv.
- **뜻밖의 결과**: 전체 주문 상태와 배송 완료 상태의 반복 고객 절대 수는 다르지만 비율은 약 3%로 비슷하다.
- **결정**: 전체 주문 지표는 식별자 함정의 대조군으로, 배송 완료 기준을 코호트·RFM·생존 주 분석으로 사용. Codex 판단.
- **한계**: 배송 완료 이전 취소·미배송 주문을 재구매 사건으로 세지 않으며 데이터셋 밖 구매 이력은 없다.

## 판단 장면 2 — 희소 월을 매출 하락으로 집계하지 않기

- **상태**: 최초 실행에서 드러난 월별 데이터 공백을 재검토.
- **맥락**: 첫 SQL 결과는 전월 LAG와 비교해 매출이 -99.96% 줄었다고 계산했다.
- **첫 가설**: 해당 급락은 실제 사업 지표 하락일 수 있다.
- **대안**: 수치를 그대로 사용, 빈 달을 0으로 채워 유지, 관측 공백과 초기 희소 기간을 분리한 뒤 연속 활동 월만 비교.
- **판단 기준**: 계절·초기 데이터 부족을 실적 변화처럼 왜곡하지 않으면서 매출 하락 원인을 고객 수·빈도·객단가로 분해.
- **실험**: results/monthly_metric_tree.csv에서 주문 수와 월 간격을 점검; 마지막 관측 월 제외, 월 500건 이상 세 달 연속인 구간을 시작점으로 적용; 그 안의 완전 연속 월에 로그 곱셈 분해 수행.
- **관측**: 유효 구간의 최대 감소는 -26.9026%; 로그 기여는 고객 수 -0.2761, 주문 빈도 -0.0032, 평균 주문액 -0.0341로 합계가 전체 로그 변화 -0.3134와 일치. 근거: results/revenue_decline_decomposition.csv.
- **뜻밖의 결과**: 초기 -99.96% 감소는 거래가 극히 적고 비연속적인 월끼리 비교한 산물이었다.
- **결정**: 500건/3개월 규칙을 분석 상수로 고정하고 그 밖의 초기 관측을 매출 하락 주장에 쓰지 않음. Codex 판단.
- **한계**: 분석 상수 500건은 민감도 분석으로 검증하지 않았다. 해당 매출 변화가 원인이나 특정 사업 조치의 효과를 뜻하지 않는다.

## 판단 장면 3 — 이벤트와 중도절단을 CSV 자료형까지 검증

- **상태**: 첫 Kaplan-Meier 요약의 불일치를 코드 디버깅으로 교정.
- **맥락**: PostgreSQL의 t/f를 CSV에서 문자열로 읽어 Python bool에 넣으면 'f'도 참이 되어 고객 전원을 두 번째 구매 이벤트로 셌다.
- **첫 가설**: 데이터에 모두 재구매 사건이 있다고 보일 때 이벤트 비율은 코드의 bool 변환 오류인지 확인해야 한다.
- **대안**: 잘못된 결과를 사용, t/f를 명시적으로 매핑, 생존 분석을 생략.
- **판단 기준**: 원본 SQL 이벤트 수와 Python 이벤트/중도절단 수가 일치해야 한다.
- **실험**: SQL 표 analytics.survival에서 repurchased 빈도를 조회하고, Python 변환 뒤 results/summary.json의 이벤트·검열 건수를 대조.
- **관측**: SQL과 Python 모두 이벤트 2,801명, 중도절단 90,557명, 총 93,358명으로 일치. 90일 무재구매 생존확률은 97.8655%. 근거: sql/02_analysis.sql, run.py, results/summary.json.
- **뜻밖의 결과**: 이벤트 분석 오류는 통계식이 아니라 CSV 불리언 문자열 해석에서 발생했다.
- **결정**: t/f/true/false 명시 매핑을 적용하고 이벤트 50% 도달이 없으므로 중앙 생존시간을 미도달로 보고. Codex 판단.
- **한계**: 생존곡선은 최초 관측 배송 주문을 고객의 실제 최초 구매로 가정하며 약 2년 바깥 재구매는 관측하지 못한다.

## Claude 반영 기준

1. WO-15는 매출·리텐션 질문에 SQL 코호트, RFM, 생존 분석, 지표 트리를 결합한 프로젝트로 소개한다.
2. 전체 주문 재구매율(3.1188%)과 배송 완료 주 분석 재구매율(3.0003%)의 분모를 구분한다.
3. customer_id를 고객 키로 썼을 때 0%가 되는 대조 결과를 명시한다.
4. 낮은 리텐션은 유지하되 관측 기간·마켓플레이스 구매 다양성은 설명 가설로만 둔다.
