# [WO-05] Claude에게 전달할 실행 결과

## 1. 코드

- 저장소: https://github.com/sth00619/Personal-Portfolio
- 브랜치: `dev/wo-05`
- 프로젝트: `projects/wo-05-injection-guard/`
- 구현: 취약한 목 에이전트, 입력 경고, 출처 격리, 맥락별 도구 허용 목록, 출력 검사, 행동 인자에 묶인 일회용 확인, 규칙별 감사 로그
- 재현: 프로젝트 폴더에서 `docker compose up --build --abort-on-container-exit --exit-code-from injection-guard`

## 2. Ship Gate

| 지표 | 실제 |
|---|---:|
| 합성 공격 60건 방어 전 성공 | 60/60 (100%) |
| 초기 가드 성공 | 1/60 (1.67%) |
| 최종 가드 성공 | 0/60 (0%) |
| 본문·메타데이터·도구 결과 방어 후 성공 | 각각 0/20 |
| 정상 이력서 100건 경고 오탐 | 2/100 (2%) |
| 정상 평가 완료 | 100/100 |
| 문자열 입력 분류기 경고 | 공격 47/60, 13건 미탐 |
| 테스트 | 8개 통과 |

## 3. 결과물

- `results/report.md`: 전후 성공률·오탐·계열별 표
- `results/comparison.png`: 채용 담당자용 비교 그래프
- `results/experiment.json`: 60개 공격과 100개 정상 사례의 상세 결과
- `results/audit.jsonl`: 모든 경고·차단의 케이스, 단계, 규칙 코드
- `results/bypass_analysis.md`: 숫자형 메타데이터 우회와 수정

## 4. 시행착오

- 입력 문자열 검사만으로는 Base64 지시 12건과 텍스트 없는 `score_hint`를 잡지 못했다. 정책 라우터가 출처와 권한을 검사하도록 했다.
- 점수 도구 자체는 정상 평가에 필요해 전면 금지할 수 없었다. 코드가 계산한 점수만 허용하고 낮은 신뢰도의 점수 힌트는 거절했다.
- 정상 보안 연구 이력서의 공격 문구는 2건의 분류기 경고를 만들었다. 경고를 지원자 전체 탈락으로 연결하지 않아 정상 평가 100건을 완료했다.

## 5. 인사이트와 전달 시 주의

- 방어의 핵심은 “모델이 속지 않는다”가 아니라 **속은 뒤 제안한 행동을 실제 도구가 거부하는 것**이다. 문자열 분류기는 13개 공격을 놓쳤지만 최종 정책은 이 코퍼스에서 모두 차단했다.
- `0/60`은 이 프로젝트가 직접 작성한 합성 코퍼스의 결과다. 실제 LLM, 이메일, ATS에서 검증한 성공률로 표현하지 말아 주세요.
- 방어 전 `60/60`도 취약한 결정적 파서가 이 코퍼스의 명령 형식을 이해하도록 설계된 기준선이다.
- 초기 가드의 1건 우회는 PDF 메타데이터 `score_hint: 100`이었다. 문자열 탐지는 침묵했지만 출처가 허용되지 않은 점수 변경이라는 행동 규칙으로 막았다.
- 면접에서는 입력 분류기의 한계, 최소 권한·완전 매개, 도구 호출 출처, 오탐의 의미, 확인 토큰의 운영상 보완점을 설명할 수 있다.
