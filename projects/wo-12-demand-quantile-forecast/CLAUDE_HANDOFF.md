## 판단 장면 1 — 공식 원본 접근과 재현 가능한 전송 경로

- 상태: 이번에 새로 검증
- 맥락: Kaggle 데이터 페이지는 공식 기준 출처지만 로그인과 대회 규칙 동의를 요구했고, 로컬에 Kaggle 자격증명이 없었다.
- 첫 가설: 공식 URL에서 인증 없이 원본 CSV를 받을 수 있을 것으로 예상했다.
- 대안: 사용자의 자격증명을 기다리거나, 공개 미러에서 같은 구조의 파일을 받아 무결성을 고정할 수 있었다.
- 판단 기준: 자격증명 보관 없이 재현 가능해야 하고, 원본 출처와 이용 조건을 숨기지 않아야 한다.
- 실험: Kaggle 페이지의 파일명·규모·이용 조건을 확인하고 `sktime/tsf-datasets` 미러의 LFS 메타데이터와 내려받은 파일의 바이트·SHA-256을 비교했다. 실행 명령은 `python data/download.py`다.
- 관측: 판매 파일 121,736,518바이트와 달력 파일 103,469바이트를 받았고, 각각의 SHA-256을 다운로드 코드에 고정했다.
- 뜻밖의 결과: 인증 부재는 분석 자체의 차단 조건이 아니었지만, 전송 경로와 이용 조건을 별도로 기록해야 출처가 오해되지 않았다.
- 결정: Codex가 공식 Kaggle 페이지를 기준 출처로, 공개 미러를 전송 경로로 분리해 기록했다. SONG의 자격증명은 사용하지 않았다.
- 한계: 미러 운영자가 파일을 제거하면 Kaggle 인증 다운로드가 필요하다.

## 판단 장면 2 — 28일 다단계 예측에서 누수 차단

- 상태: 이번에 새로 검증
- 맥락: 평가 구간 안의 `lag_1`, `lag_7`, 직전 이동평균을 실제 판매량으로 계산하면 예측 시작 시점에 모르는 값이 피처로 들어간다.
- 첫 가설: 일반적인 단기 시계열 피처를 그대로 쓸 수 있다고 보았지만, 직접 다단계 예측 조건과 맞지 않았다.
- 대안: 재귀 예측으로 이전 예측값을 입력하거나, 모든 평가 일자에서 예측 시작 전에 알려진 판매량만 쓰는 직접 예측을 구성할 수 있었다.
- 판단 기준: 모델 성능보다 평가 시점 재현과 누수 방지를 우선했다.
- 실험: `lag_28/35/42/56`과 목표일 기준 28일 전에 끝나는 이동 통계만 사용했다. `tests/test_data.py`는 예측 구간 내부 판매량을 99,999로 바꿔도 피처가 같음을 검증한다.
- 관측: 해당 누수 회귀 테스트를 포함한 테스트 9개가 통과했다.
- 뜻밖의 결과: 더 가까운 실제 판매량을 버리므로 성능 손실 가능성이 생기지만, 28개 예측일 모두 같은 정보 시점을 지키게 됐다.
- 결정: Codex가 직접 다단계 구성을 채택하고 재귀 예측은 복잡도와 오차 전파 위험 때문에 보류했다.
- 한계: 실제 운영에서 중간 판매량을 순차 관측한다면 재귀 갱신 방식과 별도 비교가 필요하다.

## 판단 장면 3 — 집계 레벨의 낮은 커버리지를 그대로 보존

- 상태: 이번에 새로 검증
- 맥락: 품목을 합치면 변동성이 완화되어 매장·카테고리 집계 구간이 더 안정적일 것으로 예상했다.
- 첫 가설: 집계 레벨 커버리지가 품목 레벨보다 80% 목표에 가까울 것으로 예상했다.
- 대안: 직접 집계 모델, 품목 분위수 합산, 계층 정합화(hierarchical reconciliation)를 비교할 수 있었다.
- 판단 기준: 먼저 동일 피처·동일 분할의 직접 집계 모델로 계층 자체의 차이를 측정하고, 검증하지 않은 정합화 결과는 주장하지 않는다.
- 실험: 1,437개 품목 합계 시계열에 같은 LightGBM 설정과 3개 워크포워드 분할을 적용했다.
- 관측: 집계 커버리지는 49/84 = 58.33%로 목표보다 -21.67%p였고, 품목 커버리지 86.82%보다 낮았다. 집계 안의 원시 분위수 교차율은 분할 평균 5.95%였다.
- 뜻밖의 결과: 집계 시계열의 값 규모와 급격한 변화를 제한된 420개 학습 목표일로 표현하지 못해 가설과 반대 결과가 나왔다.
- 결정: Codex가 낮은 수치를 Ship Gate에 그대로 기록하고, 계층 정합화와 구간 보정을 다음 검증 대상으로 남겼다.
- 한계: 집계 표본은 84건이라 품목 120,708건과 불확실성이 다르며, 원시 pinball loss는 수요 단위가 달라 레벨 간 절댓값 비교가 적절하지 않다.

## Claude가 반영할 핵심

- GitHub 루트 README에는 WO-12를 수요 분위수 예측 프로젝트로 추가한다.
- Notion에는 `README.md`의 Ship Gate 수치와 위 판단 장면 2~3개를 요약한다.
- 품목 커버리지 86.82%는 목표보다 높은 과대 커버리지이며, 집계 커버리지 58.33%는 목표 미달이다. 두 값을 성공처럼 합치지 않는다.
- 평균 pinball loss 개선 38.17%와 중앙 분위수 RMSE 악화 8.95%를 함께 써서 지표별 판단이 달랐음을 보여준다.
- 원본 데이터는 패키지에 넣지 않고 `data/download.py` 재현 명령을 안내한다.
