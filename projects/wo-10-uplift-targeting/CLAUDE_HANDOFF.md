## 공개 문서용 핵심 결과

수정본 Criteo 광고 배정 RCT 13,979,592행을 전량 감사한 뒤 결과와 무관하게 10%를 표본화했다. 처치 배정 비율은 약 85:15, 학습/검증/테스트는 838,263 / 279,421 / 279,422행이다. `exposure`는 배정 뒤 변수이므로 처치 정의와 피처에서 제외했다.

| 정책 | 검증 Qini | 테스트 Qini | 테스트 상위 20% 증분 전환 |
|---|---:|---:|---:|
| 전환 반응 | 0.1800 | 0.2020 | 290.64 |
| T 모델 | 0.0407 | 0.1500 | 277.29 |
| S 모델 | 0.0674 | 0.1190 | 246.09 |
| Class Transformation | −0.1871 | −0.1028 | 69.05 |
| Uplift Tree | 0.1018 | 0.0493 | 184.30 |
| X-learner | **0.1138** | 0.1316 | 242.40 |

검증 Qini로 선택한 X-learner의 상위 20% 증분 전환은 반응 기준선보다 **48.24건 낮았다**. 같은 테스트 행의 쌍체 포아송 부트스트랩 95% 구간은 **[−111.51, 6.26]건**으로 0을 포함한다. 따라서 업리프트 방법의 개선을 입증했다고 쓰면 안 된다. 포트폴리오의 강점은 예상과 다른 결과를 같은 RCT/예산/검증 절차로 확인하고 의사결정을 기준선 쪽으로 수정한 과정이다.

## 시행착오 → 발견 → 수정 → 결과

1. **반응 모델:** 단순히 전환 가능성이 높은 고객을 선택하면 증분 효과를 놓칠 것이라고 가정했다. 실제 보류 테스트에서는 기준선 Qini가 0.2020으로 가장 높았다. 전환 확률과 처치 효과 순위가 이 데이터에서는 상당 부분 일치할 수 있음을 발견했다.
2. **T/S 모델:** 처치별 결과 확률과 단일 상호작용을 학습해 반응 모델의 한계를 시험했다. T가 0.1500, S가 0.1190으로 둘 다 기준선에 못 미쳤다.
3. **Class Transformation:** 원본 85:15 비율은 해당 방법의 1:1 가정에 맞지 않아 학습 표본을 양 군 125,361개씩 맞췄다. 학습 가능한 행이 줄었고, 이 실행의 Qini는 −0.1028이었다.
4. **Uplift Tree/X-learner:** 트리는 100,000행 계산 예산을 명시했고, X는 전체 학습 표본을 사용했다. 검증에서는 X가 가장 좋았으나 테스트에서는 T가 X보다 높았다. 방법 선택의 변동성도 확인했다.
5. **평가 구현 점검:** scikit-uplift의 정규화 Qini 입력에 `uint8`을 쓰면 오버플로로 인공 RCT의 순위가 거꾸로 나왔다. `int64` 변환과 회귀 테스트로 고쳤다. 이는 재현 가능한 실제 디버깅 근거다.

## 4분면과 사업 해석 경계

진짜 persuadable/sure thing/lost cause/sleeping dog 개인 레이블은 RCT 한 번으로 알 수 없다. 프로젝트의 네 그룹은 T 모델의 `p0`, `p1` 및 검증 집합 경계값으로 만든 **model-implied proxy**다. persuadable 유사 그룹은 테스트의 20.06%, 선택군 실측 증분 전환 추정 270.56건 [156.38, 384.74]이었다. 익명 특성 차이 상위 3개는 `f8` −1.697, `f9` +1.636, `f0` −0.938 표준화 평균 차이다. `f0` 등의 비즈니스 의미를 상상해서 서술하지 않는다. sleeping-dog 유사 그룹의 실측 효과는 43.13건 [−21.70, 107.95]이라 해석에 신중해야 한다.

원본 처치는 **광고 배정**이고 프로모션 쿠폰 발급이 아니다. 순가치 대용치는 전환 가치 1, 선택 인원당 처치 비용 0.001을 가정한 무단위 비교다. 10% 표본에서 추정한 건수를 전체 캠페인 실적처럼 확대하지 않는다. 무작위 배정 비율이 85:15인 점도 기재한다.

## Claude에게 요청할 작업

현재 프로젝트 README와 `metrics.json`을 근거로 GitHub 루트 README의 WO-10 항목과 기존 Notion Portfolio Hub의 WO-10 케이스를 정리한다. 레포 `CLAUDE.md`의 문서화·표현 지침을 적용하고, **업리프트 모델이 기준선을 이겼다는 서사는 만들지 않는다**. 문제 정의 → 가설 → 시도 순서 → 예상과 다른 결과 → 근거와 의사결정 → 다음 검증 순서로 쓴다. 공개 문서에는 날짜·소요 시간·상대적 시간 표현을 넣지 않는다. 원본 이미지와 실측 수치를 그대로 인용한다.
