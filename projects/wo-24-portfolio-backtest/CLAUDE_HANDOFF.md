## 상태와 전달 범위

## 판단 장면 1 — KRX 요청이 비었을 때 데이터 부재로 오판하지 않기

- 상태: 이번에 새로 검증
- 맥락: 이 프로젝트의 핵심은 상장폐지주 이력인데, KRX 직접 요청은 403이고 pykrx 결과도 비어 있었다. 빈 결과를 실제 종목 수 0으로 사용하면 질문 자체가 사라진다.
- 첫 가설: pykrx가 KRX 상장폐지 종목 데이터를 제공할 수 있다.
- 대안: KRX 브라우저 표를 직접 다운로드하거나, 다른 데이터 리더로 KRX 목록과 가격을 분리 수집한다.
- 판단 기준: 상장 종목 수와 가격 이력이 실제로 반환되는지, 재실행 가능한지.
- 실험: pykrx 종목목록·기간별 가격변화 호출, KRX 데이터 마켓플레이스 페이지 확인, FinanceDataReader의 `KRX`, `KRX-DELISTING`, 일별 가격 요청.
- 관측: 직접 KRX/pykrx 경로는 이 실행 환경에서 유효한 표본을 반환하지 않았다. FinanceDataReader 목록은 KRX와 KRX-DELISTING 분류를 주었고 가격 패널은 197종목에서 반환됐다.
- 뜻밖의 결과: pykrx 문서에 상폐 관련 옵션이 있어도 이 환경의 빈 HTTP 응답에서는 이를 실측할 수 없었다.
- 결정: FinanceDataReader의 목록 제공자와 Naver Finance 가격 경로를 사용하고, 원천이 KRX 공식 직접 조회가 아님을 README·데이터 안내에 명시했다. Codex가 선택했다.
- 한계: 페이지/가격 데이터는 독립 원천 대조 및 공급자 조정 정책 검증이 끝나지 않았다.

## 판단 장면 2 — 표본 안의 우선주와 분석 모집단 구분

- 상태: 이번에 새로 검증
- 맥락: 초기 현재 종목 목록에서 우선주가 보통주 표본에 섞인 것을 발견했다. 또한 상장폐지 후보가 139개뿐인 사유 필터 범위 안에서는 60개 표본을 고집할 이유가 없었다.
- 첫 가설: KRX 주식 목록의 시장 분류와 6자리 코드만으로 보통주 표본이 구성된다.
- 대안: 종목명으로 우선주를 제외하고 현재 종목은 시장별 균등 표본으로 남기되, 사유 필터 안의 139개 상폐 종목은 전부 포함한다.
- 판단 기준: 상품 종류 혼합을 줄이고 표본에서 빠지는 상폐 후보를 줄일 것.
- 실험: `src/wo24/data.py`에서 표본을 다시 구성하고 가격 응답 수와 모집단 집계를 비교했다.
- 관측: 현재 보통주 후보 2,532개 중 60개를 뽑았고 58개 가격이 반환됐다. 상폐 후보는 사유 필터 적용 전 195개, 합병·자회사 편입·상환·만기 사유 56개를 제외한 139개 모두 가격이 반환됐다.
- 뜻밖의 결과: 일부 현재 종목 코드는 가격 제공자에서 빈 응답을 반환했다. 성공으로 꾸미지 않고 58/60으로 남겼다. 모멘텀 동률 종목의 입력 순서가 Python 집합 순회에 따라 바뀌어 재실행 결과가 흔들리는 것도 발견했다.
- 결정: 현재 상장 종목은 KOSPI/KOSDAQ에서 30개씩 균등 추출, 사유 필터 내 상폐 종목은 전체 포함. 표본 규칙·구성은 manifest에 고정했고 동률은 종목 코드 오름차순으로 결정한다. Codex가 결정했다.
- 한계: 현재 표본은 현재 목록 기반이며 과거 시점의 전체 종목 구성(panel)을 재현하지 않는다. 합병 대가·상환 현금 흐름도 모델링하지 않아 해당 56건을 제외했다.

## 판단 장면 3 — 월간 보유 구간에서 숨은 일일 재조정 제거

- 상태: 이번에 새로 검증
- 맥락: 초안은 매월 새 목표 비중을 만들었지만, 월간 구간 수익률을 매일 같은 목표 비중에 곱했다. 이는 의도와 달리 월간 보유 기간 중 매일 무료 재조정을 한 것처럼 계산한다.
- 첫 가설: 구간 수익률에 리밸런싱 시점 비중을 계속 곱하면 월간 보유를 나타낸다.
- 대안: 종목 수량을 고정하고 일별 가격 수익률로 보유 비중이 드리프트하도록 계산한 뒤, 다음 리밸런싱에서 실제 드리프트 비중과 새 목표 비중의 거래량을 비용 기준으로 사용한다.
- 판단 기준: 리밸런싱 밖의 무상 거래를 가정하지 않고 비용 계산이 실제 비중 변경을 반영할 것.
- 실험: `compound_fixed_shares`와 `test_holdings_drift_without_daily_rebalancing`을 추가했다. 두 종목 50:50에서 한 종목만 두 번 10% 상승하면 일별 포트폴리오 수익률이 5.0%, 이후 5.238%로 변해 목표 비중을 매일 복구하지 않는지 검사했다.
- 관측: 두 종목을 50:50으로 시작해 한 종목만 연속 10% 상승시키는 시험에서 포트폴리오 일간 수익률은 5.0%, 이어 5.238%가 됐다. 동률의 비결정성도 고정한 뒤 최종 확장 표본 월간·10bp는 누적 −8.5%, CAGR −1.8%, Sharpe 0.093이다. 중간 실행의 수치는 두 구현 수정이 섞여 있으므로 최종값과 직접 비교하지 않는다.
- 뜻밖의 결과: 월간 보유 회계 오류를 찾은 뒤 재실행 변동도 발견했다. 동률 점수의 종목 입력 순서를 안정화해야 결과 파일이 같은 manifest에 대해 반복 가능했다.
- 결정: 구간 내 고정 수량 방식과 실제 드리프트 기반 turnover로 교체하고 동률을 종목 코드 순으로 고정했다. 테스트 7개가 모두 통과했다. Codex가 결함을 발견하고 수정했다.
- 한계: 실제 브로커 체결, 세금, 배당, 거래정지 중 청산, 상장폐지 회수금, 합병 대가 모델은 없다.

## 실행 및 남은 작업

- 검증: `python -m pytest -q` 결과 7 passed.
- 데이터·결과: 전체 파이프라인이 가격 패널 1,728×197을 읽어 시나리오 8개를 산출했다. 현재 표본 수집 누락 2건, 상폐 표본 누락 0건.
- 컨테이너: `docker compose config`는 통과했다. 이 실행 환경의 Docker 빌드 컨테이너가 호스트와 같은 패키지 저장소에 접근하지 못해 이미지 빌드는 완료하지 못했다.
- Sharpe 3 초과 결과가 없어 비정상 고Sharpe 원인 분해는 발동하지 않았다. 본 표본에서는 손실·저성과와 표본 정의, 가격 조정 경계가 주요 해석 대상이다.
- 남은 작업: 시점별 KRX 상장 구성, 합병/상환/회수 자료, 기업행위 조정, 거래정지 체결 제한을 확보해 전체 시장 패널로 넓힌다.
