# Claude 요청 — WO-24 GitHub·Notion 정리

동봉한 WO-24 프로젝트 파일을 근거로 GitHub 프로젝트 설명과 기존 Notion Portfolio Hub의 WO-24 페이지를 정리해 주세요.

## 해야 할 일

1. GitHub 레포 루트 README의 WO-24 항목 또는 프로젝트 목록에 프로젝트를 추가하고, 프로젝트 폴더 README의 핵심 질문·접근·결과와 연결해 주세요. 기존 문서 구조와 표현 규칙을 유지해 주세요.
2. 기존 Notion Portfolio Hub 안에 WO-24 케이스 스터디를 추가하거나 해당 WO-24 페이지를 갱신해 주세요. 아래 비교 결과, 표본 경계, 시행착오, 트러블슈팅, 면접 질문과 답변 근거를 읽기 쉽게 정리해 주세요.
3. 현재 종목 표본과 상장폐지 전체 후보 139개가 비대칭이라는 점, 상폐 후보 195개 중 56개 사유를 제외한 점, 현재 가격 이력 58/60·상폐 가격 이력 139/139를 명시해 주세요.
4. 최종 월간 10bp 결과만 사용해 주세요: 현재 표본 누적 수익률 64.9%, CAGR 10.8%, Sharpe 0.488, MDD −38.1%; 상폐 포함 표본 누적 수익률 −8.5%, CAGR −1.8%, Sharpe 0.093, MDD −48.8%. 차이는 누적 수익률 −73.4%p, CAGR −12.6%p, Sharpe −0.394, MDD −10.7%p입니다.
5. 핸드오프에 기록된 잘못된 일일 목표 비중 재설정, 동률 순서 비결정성, 고정 수량 방식 수정은 중요한 시행착오로 설명해 주세요. 수정 전 숫자는 최종 성과처럼 섞지 말고 “수정 전 중간 계산”으로 구분해 주세요.
6. 사용한 모델·리밸런싱·거래비용 가정, 결과·해석·측정 경계를 포트폴리오 독자가 이해할 수 있는 표현으로 요약해 주세요.

## 반드시 지킬 표현 규칙

- README 및 Notion 본문에는 날짜, 기간 표현, 작업 소요 시간, “오늘/최근/이번 주” 같은 상대 시점을 넣지 마세요.
- 처음 등장하는 전문용어는 한국어(English)로 병기하고, 페이지 맨 아래 “📖 용어집”을 관련 링크 섹션 바로 앞에 추가하세요.
- 수치는 결과 CSV·JSON과 일치시켜 주세요. 이 표본 결과를 전체 한국 시장의 보편적인 생존 편향 인과 효과처럼 쓰지 마세요.
- 측정 경계는 한 번 담백하게 요약하고, 한계는 다음 단계로 제시하세요.
- 작업 과정은 결과 나열 대신 “가설 → 데이터 접근 실패 확인 → 대체 경로 → 우선주 표본 정제 → 숨은 일일 재조정 오류 수정 → 최종 수치” 순서로 보여 주세요.
- GitHub 또는 Notion에 아직 반영하지 않았다면, 반영 완료라고 보고하지 말고 어떤 문서를 실제로 수정했는지 구분해 주세요.
